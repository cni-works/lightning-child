# Lightning Child

無料テーマLightningの現行G3世代を親テーマとして使用する、再利用可能な調整用子テーマです。無料版で実務上必要性が高い表示機能だけを、WordPress標準APIとLightningの公開フックで追加します。

## 動作対象

- Lightning G3
- 調査・開発時の親テーマ: Lightning 15.37.1
- WordPress 6.5以上
- PHP 7.4以上
- Lightning G3 Pro Unit、VK Blocks Proは不要

親テーマのフォルダ名は `lightning` のまま使用してください。

## 実装済み機能

### 固定ページごとの表示設定

固定ページの編集画面に「Lightning 表示設定」を追加します。

- ヘッダーを表示しない
- ページヘッダーを表示しない
- パンくずリストを表示しない
- フッターを表示しない

ブロックエディターとクラシックエディターの両方に対応します。フッターを非表示にした場合は、Lightningのフッター直前ウィジェットも非表示になります。モバイルナビはページ別非表示の対象に含みません。

### ページヘッダー

「外観」→「カスタマイズ」→「Lightning ページヘッダー設定」で、共通画像、投稿タイプごとのPC／モバイル画像・タイトル・サブタイトル・配色・高さを設定します。投稿タイプ別画像が未選択の場合は共通画像を使用し、モバイル画像だけ未選択の場合は同じ投稿タイプのPC画像を使用します。投稿と公開カスタム投稿タイプでは、個別ページと一覧・アーカイブのページヘッダーを別々に非表示にできます。投稿の一覧設定は投稿一覧、カテゴリー、タグ、日付、投稿者アーカイブへ適用し、共有カスタム分類は対象外です。

ブロックエディターを使用する公開カスタム投稿タイプでは、個別設定をREST API経由で保存できるように、WordPress標準の `custom-fields` サポートを子テーマが補います。

固定ページ、投稿、管理画面を持つ公開カスタム投稿タイプの編集画面には「ページヘッダー個別設定」を追加します。「このコンテンツで個別設定を使用する」を有効にすると、次を投稿ごとに設定できます。

- キャッチフレーズ
- サブテキスト
- 背景画像（PC）
- 背景画像（モバイル）
- オーバーレイの色と透明率

個別設定が無効な場合は共通・投稿タイプ別設定を継承します。有効な場合、文章の空欄は非表示、PC画像の未選択は背景画像なしとして扱います。モバイル画像だけ未選択の場合はPC画像を使用します。「オーバーレイを個別設定する」が無効な場合は投稿タイプ別の色と透明率を引き継ぐため、固定ページなどで画像だけ変更してもオーバーレイは維持されます。固定ページの「ページヘッダーを表示しない」が有効な場合は、個別設定より非表示が優先されます。ブロックエディターとクラシックエディターの両方に対応します。

### ヘッダー

「外観」→「カスタマイズ」→「Lightning 子テーマ ヘッダー」で設定します。

- Lightning標準ヘッダー／作成済みヘッダーテンプレートパーツの選択
- Lightning標準／ロゴ・ナビゲーション中央寄せレイアウト（標準ヘッダーのみ）
- 背景色と文字色
- トップページの透過ヘッダー
- 透過時の文字色
- スクロール後の背景色
- モバイルのロゴ位置（標準ヘッダーのみ）
- PCロゴの表示（常に表示／ファーストビューだけ非表示／常に非表示）
- モバイルロゴの非表示（標準ヘッダーのみ）

「ファーストビューだけ非表示」はPCにだけ適用し、スクロール後は「グローバルナビ スクロール時のレイアウト」に従います。「固定 ロゴ＆ナビ回り込み」と組み合わせると、初期表示はナビだけ、スクロール後はロゴ付きにできます。モバイルロゴを非表示にした場合も、Lightning標準ハンバーガーボタン用の高さを維持します。ブロック式ヘッダーのロゴ表示はテンプレートパーツ側で調整します。

複雑なヘッダーレイアウト、高さ検出の独自最適化は実装していません。

### フッターとコピーライト

「外観」→「カスタマイズ」→「Lightning 子テーマ フッター」で設定します。

- Lightning標準フッター／作成済みフッターテンプレートパーツの選択
- 背景色と文字色
- Lightning標準のテーマクレジットを独自コピーライトへ置換
- `{year}` を現在年へ置換
- `{site_name}` をサイト名へ置換
- コピーライトが空欄の場合は領域ごと非表示

ブロックフッターでも同じコピーライト設定を使用し、標準コピーライトは重複表示しません。フッターの背景色・文字色はLightning標準フッターと、子テーマが追加するコピーライト領域だけへ適用します。「外観」→「デザイン」→「パターン」→「フッター」で作成したブロック部分には強制せず、各ブロックで設定した配色を使用します。

### 投稿タイプ別の詳細ページ表示

「外観」→「カスタマイズ」→「Lightning 子テーマ 投稿表示」で設定します。

- 公開日
- 更新日
- 投稿者名と投稿者画像
- 前の記事・次の記事

「投稿」と、管理画面を持つ公開カスタム投稿タイプが対象です。固定ページと添付ファイルは除外します。

### ブロックテンプレートパーツ

WordPress標準のクラシックテーマ向けブロックテンプレートパーツ機能を有効にしています。

- `parts/header.html`
- `parts/footer.html`

管理画面の「外観」→「デザイン」→「パターン」でテンプレートパーツを編集し、カスタマイザーで使用するヘッダー／フッターを選択します。通常のパターンではなく、「ヘッダー」または「フッター」領域のテンプレートパーツが選択肢に表示されます。新しく作成した場合は、カスタマイザーを開き直してください。

ブロックヘッダーではWordPress標準のナビゲーションブロックを使用します。Lightningのモバイルナビは重複防止のため停止します。ブロックヘッダーのサイトロゴとLightning標準ヘッダーのロゴは別の設定です。

### モバイル固定ナビとハンバーガーメニュー

「外観」→「カスタマイズ」→「Lightning モバイル固定ナビ」で設定します。通常リンクは4件または5件まで設定でき、リンクテキスト、Font Awesomeクラス、URL、別ウィンドウ表示を項目ごとに指定できます。

「ハンバーガーメニュー」を有効にすると、固定ナビの左端にメニュー項目を追加します。表示内容は次から選択できます。

- フッターテンプレートパーツ（通常フッターと同じもの、またはハンバーガー専用の別パーツ）
- 「外観」→「デザイン」→「パターン」→「マイパターン」で作成した公開済みパターン

マイパターンを新しく作成した場合は、カスタマイザーを開き直すと選択肢へ追加されます。ハンバーガー画面の背景色と文字色はモバイル固定ナビ設定で指定します。

- 選択したフッターまたはマイパターンが未選択、削除済み、非公開、空の場合、メニュー項目を出力しない
- メニュー項目がない場合も、設定済みの通常リンクはそのまま表示する
- JavaScriptの初期化に成功した場合だけ専用ドロワーを有効にし、Lightning標準ハンバーガーボタンを隠す
- 通常フッターはPC・スマートフォンともページ下部へ表示し、ドロワーとは独立させる
- Escapeキー、背景クリック、閉じるボタンに対応し、開いている間はフォーカスをパネル内に保つ

通常フッターと同じテンプレートパーツを選べば、PCフッターとスマートフォンのスライドメニューを一か所で管理できます。用途を分けたい場合は、別のフッターテンプレートパーツまたはマイパターンを選択します。フォームやHTMLアンカーを含む内容をフッターとドロワーの両方へ表示すると識別子が重複する可能性があるため、その場合はハンバーガー専用の内容を選択してください。

### フォント

「外観」→「カスタマイズ」→「Lightning 子テーマ フォント」で選択します。

- OS標準サンセリフ
- 日本語ゴシック
- 日本語明朝
- Noto Sans JP（Google Fonts）
- Noto Serif JP（Google Fonts）

Noto Sans JPまたはNoto Serif JPを選択した場合だけ、選択された書体をGoogle Fontsから通常・太字（400／700）で読み込みます。Google Fontsを選択していない場合は、子テーマから外部フォントを読み込みません。Origin IIIの固定的なGoogle Fonts読み込みは子テーマから解除し、選択した書体との重複読み込みを防ぎます。

## ファイル構成

```text
lightning-child/
├─ assets/
│  ├─ images/
│  └─ js/
│     ├─ mobile-fixed-nav.js
│     ├─ page-header-classic.js
│     ├─ page-header-panel.js
│     └─ page-visibility-panel.js
├─ inc/（機能別PHPファイル）
├─ parts/
│  ├─ footer.html
│  └─ header.html
├─ AGENTS.md
├─ PROJECT-BRIEF.md
├─ README.md
├─ functions.php
├─ style.css
└─ theme.json
```

親テーマのテンプレートは子テーマへコピーしていません。

## 保存データ

- 固定ページの表示設定: 子テーマ専用のboolean投稿メタ
- 固定ページ・投稿・公開カスタム投稿タイプのページヘッダー個別設定: 子テーマ専用の文字列・画像ID・色・数値・boolean投稿メタ
- カスタマイザー設定: 子テーマ専用のtheme mod
- 編集したブロックテンプレートパーツ: WordPress標準の `wp_template_part`

ページヘッダーと固定ページ表示設定の投稿メタはREST APIへ登録し、編集権限を持つ利用者だけが更新できます。クラシックエディターの保存処理では権限とnonceを確認します。

## 導入方法

1. 親テーマLightningをインストールします。
2. `lightning-child` フォルダをZIP化します。
3. WordPress管理画面の「外観」→「テーマ」→「新規追加」→「テーマのアップロード」から追加します。
4. 「Lightning Child」を有効化します。
5. カスタマイザーで必要な設定を行います。
6. ブロックヘッダーを使用する場合は、テンプレートパーツ編集画面でサイトロゴとナビゲーションを設定します。

本番サイトへ直接導入せず、ローカルまたはステージング環境で確認してください。

## 既知の制限

- Lightning G3専用です。
- Lightning標準テンプレートを使用しない独自投稿タイプでは、投稿情報設定が反映されない場合があります。
- WooCommerceなど独自テンプレートを持つプラグインの詳細画面は対象外です。
- ブロック内部で背景色や文字色を明示すると、子テーマのヘッダー／フッター配色よりブロック側の設定が優先される場合があります。
- Lightning G3 Pro Unitのブロックテンプレートパーツ機能との同時使用は想定していません。
- テンプレートパーツを管理画面で編集した後は、データベース側の編集内容が子テーマ同梱HTMLより優先されます。

## 更新時の不具合回避

Lightning、WordPress、PHP、主要プラグインを更新する前に、動作確認済みの親テーマと子テーマのZIP、データベース、各バージョンを保存してください。本番サイトへ先に適用せず、ステージング環境で下記の手動確認を行います。

更新後にヘッダー、モバイルメニュー、ブロックテンプレートパーツ、アーカイブ表示のいずれかで問題が起きた場合は、`wp-config.php` の「編集が必要なのはここまでです」の行より前へ次を追加すると、更新依存の強い機能をまとめて停止できます。

```php
define( 'LIGHTNING_CHILD_SAFE_MODE', true );
```

セーフモードでは、ヘッダー拡張、モバイル固定ナビ、ブロックテンプレートパーツ、アーカイブ表示設定、ページヘッダー拡張を読み込まず、Lightning標準表示を優先します。固定ページの表示設定、コピーライト、投稿詳細表示、ページトップ、追尾ボタン、フォント設定は継続します。管理画面にはセーフモード中であることを示す警告が表示されます。

原因を絞り込む場合は、セーフモードの代わりに必要な機能だけを停止できます。

```php
define( 'LIGHTNING_CHILD_DISABLE_HEADER_ENHANCEMENTS', true );
define( 'LIGHTNING_CHILD_DISABLE_MOBILE_FIXED_NAV', true );
define( 'LIGHTNING_CHILD_DISABLE_BLOCK_TEMPLATE_PARTS', true );
define( 'LIGHTNING_CHILD_DISABLE_ARCHIVE_LAYOUT', true );
define( 'LIGHTNING_CHILD_DISABLE_PAGE_HEADER', true );
```

複数を同時に指定できます。確認後は不要な定数を削除し、キャッシュを消してから再確認してください。子テーマ全体を無効化する前に、まずセーフモードまたは個別停止を使用します。

## 手動確認

更新後は少なくとも次を確認します。

1. 固定ページの4つの非表示設定を個別に保存・解除できる。
2. 標準ヘッダーとブロックヘッダーを切り替えても重複表示しない。
3. ブロックヘッダーのPCナビとモバイルメニューが操作できる。
4. トップページ透過とスクロール後の背景色が切り替わる。
5. 標準フッターとブロックフッターを切り替えても重複表示しない。
6. コピーライトの置換と空欄時の非表示が機能する。
7. 投稿タイプごとの公開日・更新日・投稿者・前後記事設定が反映される。
8. フォント設定がフロント画面とブロックエディターへ反映される。
9. PC、タブレット、スマートフォンで横スクロールや要素の重なりがない。
10. ログイン中の管理バー表示時も固定ヘッダーが正しい位置に表示される。
11. ハンバーガーの表示元として、フッターテンプレートパーツと公開済みマイパターンを切り替えられる。
12. スマートフォンで通常フッターがページ下部に残り、固定ナビから専用ドロワーが左から表示され、閉じるボタン、背景クリック、Escapeキーで閉じられる。
13. 選択元を削除・非公開・空にするとメニュー項目が消え、Lightning標準モバイルメニューが残る。
14. 固定ページ・投稿・公開カスタム投稿タイプのキャッチフレーズ、サブテキスト、PC／モバイル画像、個別オーバーレイを保存・解除できる。
15. 固定ページの個別設定を無効にすると共通ページヘッダー設定へ戻る。
16. 投稿とカスタム投稿で、個別ページとアーカイブの非表示設定が別々に反映される。
17. PCからスマートフォン幅へ変更した際、閉じる方向のドロワーアニメーションが一瞬表示されない。
18. ブロックフッター本体の背景色・文字色が子テーマのフッター配色で上書きされない。
19. PCロゴの3種類の表示設定とモバイルロゴ非表示が、標準ヘッダーだけに反映される。
